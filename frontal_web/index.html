Code Visualizer is a free, open-source desktop app that shows the dependency graph of your repositories, one tab per repository: callers, callees and inheritance of any function, class or file. IDE extensions link it to your code in both directions: open the symbol under your cursor in the graph, and jump back to its code from any node.

Why use it

A text search finds names. Here, the graph follows actual calls and stays in sync with the code you are editing.

IDE ↔ graph navigation

From the editor, Cmd/Ctrl+Alt+G with the VS Code or Cursor extension opens the symbol under the cursor in the app, centred on it. From the graph, a node opens its code in VS Code, Cursor, Rider, IntelliJ or Zed.

The same graph for your AI agent

An MCP server gives Claude Code, Cursor, Copilot in VS Code, Codex and other agents the graph you see: search code by meaning, walk callers and callees to assess the impact of a change, read the code of a symbol. cviz mcp setup configures your agent.

Always up to date

The watcher pushes changes to open pages, catches up on start-up with files modified while it was not running, and re-links callers after a rename.

Local by design

Everything is embedded: LadybugDB (no server, no credentials) and a local embedding model, so nothing leaves your machine. One index per repository, in .code-visualizer/ (ignored by Git). The LLM used by search is optional and configured by default for a local Ollama or LM Studio.

Features

Desktop app
macOS, Windows and Linux. One tab per repository, restored at the next start (Cmd/Ctrl+O opens one). Opening a folder indexes it, then keeps it up to date as you edit. Nothing else to install.
Supported languages
Python, JavaScript, TypeScript (TSX), Java, C#, C, C++, Go, Rust, Swift, Kotlin, Scala, PHP, Ruby, Dart, Elixir, Haskell, Lua, Perl, Solidity, Vue, Svelte, HTML, CSS, HCL (Terraform) and Emacs Lisp.
Callers, callees, inheritance
For a function, class or file, from 1 to 5 levels deep. A click adds a node's neighbours to the graph, a double click recentres on it. Heuristic edges can be hidden.
Changes view
Compares the current state with a target branch: added, modified, moved, renamed and deleted artifacts.
IDE extensions
They link the graph to the code in both directions. VS Code and Cursor: .vsix extension, command "CViz: Open in Dependency Graph" (Cmd/Ctrl+Alt+G). Rider, IntelliJ and other JetBrains IDEs: External Tool installed by cviz ide jetbrains. Zed: task installed by cviz ide zed /path/to/repo. A node's "Open in IDE" goes back to the code.
Open in the graph
When the app is running, it comes forward on the repository's tab, centred on the symbol under your cursor (opened and indexed first if needed). Otherwise the graph page opens in the browser. From a terminal: cviz-open FILE:LINE.
Live updates
The watcher pushes changes to open pages (SSE), catches up on files changed while it was stopped, and re-links calls to symbols defined after their callers and after a rename.
Calls resolved by type
C#, Rust, TypeScript and Swift: a method call is bound through the receiver's declared type. Interface, trait and protocol calls go to an implementation, marked as heuristic.
Natural-language search
A hybrid search box (meaning and keywords), at most 5 results, each linked to its node. An optional LLM, configured by default for a local Ollama or LM Studio (any OpenAI-compatible server works), re-ranks results and answers how / why questions.
One index per repository
LadybugDB database stored in the repository, dedicated server on port 9324 (or the next free one). Vectors are computed at start-up with a local multilingual model or an embedding server.
Large repositories
Two-stage indexing: the page opens after the first 1,000 files, the rest follows in the background with a progress badge.
HTTP API
/api/locate, /api/neighborhood, /api/events, /api/focus, /api/open, /api/search, /api/chat.

Get started

Install the app, add the extension for your IDE, then open a repository with + (or Cmd/Ctrl+O). The command line is only needed for the JetBrains and Zed extensions, the MCP server for AI agents, a terminal or a remote machine.

# 1. install the desktop app (see the tab for your system below)
# 2. install the extension for your IDE (VS Code / Cursor: Extensions › … › Install from VSIX)
# 3. open a repository in the app: + or Cmd/Ctrl+O

# optional, command line: open the graph of the current repository in the browser
cviz graph --watch .      # http://localhost:9324/graph
# open a specific location in the graph
cviz-open src/app.py:42

On a large repository, the page opens once the first 1,000 files are indexed (code before tests and generated files) and the rest is indexed in the background. cviz config set GRAPH_FIRST_PASS_FILES 3000 changes that size.

Connect your AI agent (MCP)

The MCP server gives your coding agent five read-only tools on the graph: an overview, code search, callers and callees, a symbol's code, and Cypher queries. It needs the command line.

# configure your agent: pick it from the list (Claude Code, Claude Desktop,
# Cursor, VS Code, Windsurf, Zed, Gemini CLI, Codex, Cline, JetBrains AI...)
cviz mcp setup

# or by hand, Claude Code
claude mcp add code-visualizer -- cviz mcp start

# or by hand, any agent: its MCP configuration
{ "mcpServers": { "code-visualizer": { "command": "cviz", "args": ["mcp", "start"] } } }

# a client without project folders (Claude Desktop): name the repository
"args": ["mcp", "start", "--repo", "/path/to/repo"]

Which repository: --repo when given, else the project folder the client announces (VS Code, Cursor and other clients send it), else the folder the agent runs in (Claude Code, Codex, Gemini CLI). The MCP server goes through the graph server of that repository, the one the app or cviz graph runs, so the agent and the graph share one index; when none runs, it starts one, indexing the repository the first time.

Frequently asked questions

What is Code Visualizer?

Code Visualizer is a free, open-source desktop app for macOS, Windows and Linux that shows the dependency graph of a code repository: the callers, callees and inheritance of any function, class or file. IDE extensions link the graph to the code in both directions.

Is Code Visualizer free?

Yes. It is open source under the MIT License, with no account, no subscription and no server to run.

Which programming languages does it support?

Python, JavaScript, TypeScript (TSX), Java, C#, C, C++, Go, Rust, Swift, Kotlin, Scala, PHP, Ruby, Dart, Elixir, Haskell, Lua, Perl, Solidity, Vue, Svelte, HTML, CSS, HCL (Terraform) and Emacs Lisp. In C#, Rust, TypeScript and Swift, method calls are also resolved through the receiver's declared type.

Does my code leave my machine?

No. Indexing, the graph database (LadybugDB, embedded) and the embedding model used by the search all run locally. The LLM that re-ranks search results is optional and set up by default for a local Ollama or LM Studio.

Which IDEs work with it?

VS Code and Cursor (a .vsix extension), Rider, IntelliJ and the other JetBrains IDEs (an External Tool) and Zed (a task). From the editor, the symbol under the cursor opens in the app; from the graph, a node opens its code in the IDE.

Does it handle large repositories?

Yes. The first index runs in two stages: the graph opens once the first 1,000 files are indexed (code before tests and generated files) and the rest is indexed in the background. The graph then stays up to date as you edit.

How is it different from a text search?

A text search finds names. Code Visualizer follows the calls and inheritance it resolved when indexing, so a call on a standard-library object such as a Mutex or a Map does not link to a same-named method of your project, and the Changes view shows what a branch added, modified, moved, renamed or deleted.

Good to know

/ Only one process opens the LadybugDB database at a time: one cviz graph instance per repository.
/ Receiver-type resolution covers C#, Rust, TypeScript and Swift. Elsewhere, call resolution does not use the receiver's type.
/ The desktop apps are not signed: macOS and Windows ask for a manual approval on first launch.
/ The JetBrains and Zed extensions run cviz-open: they need the command line installed.
